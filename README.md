# Telegram Guard

Локальный MCP-инструмент для работы AI-агентов с Telegram от личного аккаунта.
Основное ядро проверяет права доступа к чатам и поручения на исходящие действия;
интеграция с Codex Desktop добавляет доставку внешних событий в текущий чат агента.

## Возможности

- Чаты и папки, история, поиск, сведения о чатах и участниках, темы форумов.
- Получение отдельных сообщений, метаданных опросов и скачивание вложений.
- Отправка текста и поддерживаемого медиа, пересылка, редактирование, удаление,
  реакции, закрепление, отметка прочтения и голосование.
- Входящие события через MTProto Updates, ограниченный буфер, подписки с фиксированным сроком.
- Локальный браузерный редактор прав для человека.
- Дополнительный native stdio bridge для Codex и интеграция с agent-wake.

MCP предоставляет 21 отдельный именованный инструмент. Произвольного Telegram RPC
в аргументах инструмента нет. Список: [tools.py](telegram_guard_local/tools.py).

## Модель доступа

Чтение по умолчанию доступно во всех чатах, кроме read-blacklist. Запись ограничена
write-whitelist. Разрешение записи в чат само по себе не является поручением отправить
сообщение: для каждого исходящего действия проверяется отдельная человеческая
авторизация с областью действия, источником поручения и сроком.

Разрешение чтения охватывает историю, поиск и скачивание вложений. Мониторинг требует
отдельного поручения и не разрешает автоматически отвечать. Содержимое Telegram
рассматривается как недоверенные данные, а не инструкции для расширения доступа.

Квитанции исходящих действий сохраняются. При неопределённом результате сообщение
не повторяется автоматически. API-ключи, Telegram session и внутренние peer-секреты
не выдаются через MCP. Вложения сохраняются под случайными именами с SHA-256.

Редактор доступов работает только на loopback; настройки сохраняет человек.
Агент может открыть редактор, но не должен автоматизировать его настоящую страницу.
Подробнее: [telegram-send](skills/telegram-send/SKILL.md).

## Устройство проекта

| Каталог | Назначение |
| --- | --- |
| `telegram_guard_local/` | MCP, политика, брокер Telegram, операции, стриминг и интеграция Desktop |
| `skills/telegram-send/` | Инструкции агенту и описание операций |
| `deploy/` | Установка, настройка и обновление локальных компонентов |
| `tests/` | Автоматические тесты и отдельные интеграционные probes |
| `docs/` | Проверки и история реализации |

Один локальный брокер владеет подключением Telegram и обслуживает MCP-процессы.
Опциональный native bridge оставляет управление App Server у Desktop, а внешним
источникам предоставляет ограниченный аутентифицированный канал событий.

## Установка и разработка

Основной проверенный сценарий — Windows и Codex Desktop. Требуется Python 3.11+.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
.\.venv\Scripts\python.exe -m pytest -q
```

Для установки отдельного локального runtime:

```powershell
.\.venv\Scripts\python.exe deploy/install_local.py
```

Установщик создаёт runtime в `~/.codex/telegram-local` и отдельный профиль разрешений.
Существующий профиль не перезаписывается без специального параметра. Настройка MCP
в обычном Desktop выполняется через `deploy/configure_desktop.py` после проверки
существующей конфигурации. Вход в Telegram выполняет человек через установленный
`telegram-setup.ps1`; реквизиты получают на [my.telegram.org](https://my.telegram.org).
Каталог `skills/telegram-send` нужно установить в каталог skills используемого агента.

Файловые профили зависят от версии и возможностей агентского приложения. Политика
внутри MCP не делает произвольные другие Telegram-клиенты безопасными. Полный доступ
к ОС, изменение защищённого кода или иной транспорт находятся за границей этой модели.

## Дополнительная интеграция Codex Desktop

Для native stdio режима нужен установленный Codex и совместимый Node runtime.
Скопируйте `deploy/native-shared-desktop.example.json` в
`deploy/native-shared-desktop.json` и заполните пути своей установки и `codex_home`.
Конфигурация конкретного компьютера игнорируется Git; секретов в примере нет.

Launcher обнаруживает новую Store-сборку, проверяет нужные возможности протокола
по локально сгенерированной JSON Schema и сохраняет положительный результат по
SHA-256 CLI. Номер версии сам по себе не блокирует совместимое обновление.
Открытый Desktop и его задачи launcher не перезапускает.

Скрипты `install_native_launcher.py`, `install_auto_launcher.py` и
`install_agent_wake_runtime.py` обновляют соответствующие установленные компоненты
с резервной копией. Часть интеграции ожидает отдельно установленный agent-wake:
полный CLI/worker agent-wake не входит в этот репозиторий. Здесь находятся его
Node bootstrap и клиент ограниченного event bridge.

## Проверки и ограничения

Полный набор тестов перед публикацией: **271 passed**.
Сценарии и границы проверки: [docs/verification.md](docs/verification.md).
Работы и ограничения: [TECH_DEBT.md](TECH_DEBT.md).
История версий: [docs/implementation-notes.md](docs/implementation-notes.md).

Приложение Telegram и Telegram API могут ограничивать отдельные действия по правам
участника, типу чата и защите содержимого. Для пробуждения агента Desktop должен быть
запущен, а нужный чат — загружен. Объявление совместимой схемы протокола не гарантирует
отсутствие любых ошибок будущей сборки Desktop. Полная изоляция от процессов с правами
той же учётной записи ОС не заявляется.

Переписки, аккаунты, ключи, whitelist, машинные конфигурации, резервные копии и локальные
результаты реальных проверок в репозиторий не входят.
