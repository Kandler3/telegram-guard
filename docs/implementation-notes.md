# История реализации

Этот документ сохраняет описание этапов разработки. Для текущего поведения и установки используйте корневой README. Исторические ограничения и команды старых версий могут отличаться от актуального native stdio режима.

# Telegram Guard Local 2.6.2

## Автоматическая совместимость launcher после обновлений

Launcher сам находит текущий Store-пакет Codex, его packaged CLI и установленный
Node runtime. Прежние файлы могут ещё существовать: это не мешает выбрать новый
пакет. Номер версии сохраняется только для диагностики и не блокирует запуск.

Для нового CLI локально генерируется схема протокола и проверяются необходимые
методы initialize, thread/loaded/list, thread/read, thread/name/set и turn/start,
включая объявленные поля toolOutput для Telegram и agent-wake. Проверка использует
временный CODEX_HOME без аккаунта, реальных инструментов и запросов к модели;
внешние ссылки схемы не загружаются. Node проверяется на необходимые WebSocket/
crypto-возможности. Результат проверки схемы кэшируется по SHA-256 CLI и ревизии
проверяющего кода, а не по строке версии.

При успешном запуске новые пути сохраняются автоматически с резервной копией
публичной конфигурации; порт, CODEX_HOME и правила доступа сохраняются. Неподдерживаемый
метод/формат или невозможность проверить целостную установку дают конкретную ошибку.
Проверка объявления протокола не гарантирует отсутствие всех ошибок будущего Codex.
Открытый Desktop не закрывается и не перенастраивается launcher. Команда Check
обнаруживает обновление и сообщает configuration_refresh_needed, но не сохраняет
конфигурацию или кэш. Установка этого изменения: deploy/install_auto_launcher.py.

## Native stdio launcher и доставка событий

PowerShell bootstrap agent-wake независимо обнаруживает совместимый Node: сначала
проверяет сохранённый путь, затем существующие cua_node runtime и bundled primary
runtime Codex. Исчезновение старого Node после обновления не требует перезапуска
Desktop для запуска agent-wake. Проверяются WebSocket и node:crypto, каждый probe
ограничен пятью секундами. Произвольный node.exe из PATH/рабочего каталога не используется.
Конфигурация Desktop, авторизация, очередь заданий и окружение команды не меняются.
Установка: deploy/install_agent_wake_runtime.py. Это не восстанавливает отдельно
сломавшийся event bridge или sandbox helper, а только выбор Node для CLI agent-wake.

«Codex + Telegram» открывает Desktop без предварительного запуска отдельного App
Server. Адаптер запускает настоящий CLI с исходными аргументами и окружением
Desktop. Браузерные каналы, инструменты приложения и подтверждения остаются в
штатном stdio-процессе. Ранней обязательной проверки браузерного окружения нет.

При переходе используется свободный порт 48964; прежний listener на 48963 не
завершается установщиком. Loopback endpoint из shared-desktop.json обслуживает ограниченный event bridge,
а не самостоятельный App Server. Telegram Guard и agent-wake проходят взаимную
HMAC-аутентификацию с одноразовым challenge; ключ меняется при запуске и хранится
в CODEX_HOME/event-bridge/auth.json с Windows ACL текущего пользователя и SYSTEM.
Значения ключей и native-service параметров не выводятся. Endpoint запрещает
браузерные Origin, user input, изменение конфигурации, ответы на approvals и
доставку в чаты, которые Desktop не открывал. Роли разделяют пространства имён
telegram_guard/telegram_incoming и agent_wake/event_completed.

Существующие очереди сохраняют accepted/rejected/unknown и не повторяют отправку
при потерянном ответе. После закрытия Desktop native server прекращает работу;
события ждут доступного подключения в пределах прежних сроков. Пробуждение при
полностью закрытом приложении этим launcher не поддерживается.

Отказ event endpoint не завершает native stdio. Launcher не закрывает открытые
задачи и отказывается использовать неизвестный процесс на занятом порту.
После обновления пути обнаруживаются автоматически, а совместимость проверяется
по возможностям протокола независимо от изменения номера версии.

Установка: deploy/install_native_launcher.py. Он сохраняет адресную резервную
копию launcher-модулей и Node-клиента agent-wake, проверяет SHA-256 и создаёт
rollback.ps1. Применение происходит при следующем полном запуске существующей
иконкой. Интеграционный offline-тест: tests/probe_authenticated_stdio.mjs. Флаг
--installed-adapter с абсолютным путём codex-shared-stdio.exe проверяет
установленный executable с отдельным CODEX_HOME и отключённым synthetic MCP.
Он проверяет настоящий native CLI и обе реализации клиентов через локальную
модель. Это не заменяет контроль запуска Electron Desktop, браузера и approvals
после переключения. До этого UI-проверка остаётся незавершённой.

## Устойчивый локальный транспорт Desktop — 2.6.2

Desktop использует штатный stdio через `codex-shared-stdio.exe`; текущая схема
единственного native runtime описана выше. Telegram и agent-wake продолжают
подключаться к прежнему endpoint. Сборка Desktop, глобальные настройки и политики
доступа не патчатся. CLI-диагностика адаптера делегируется настоящему codex.exe.

В прежнем режиме Desktop напрямую использовал WebSocket; в журналах подтверждены
разрывы `pong_timeout` и обращения к уже закрытому сокету из служебных запросов.
У нового локального адаптера нет heartbeat-дедлайна: отсутствие интернета и скачок
часов после сна сами по себе не закрывают управляющий канал. Сетевые ошибки модели
сохраняют обычный протокол ошибки запроса, а не завершают управляющий процесс.

Адаптер прозрачно передаёт запросы подтверждения в Desktop и ответы человека обратно.
Он не подтверждает действия, не возобновляет чаты, не перезапускает сервер и не
повторяет запросы. При действительном закрытии локального соединения адаптер
завершается с ошибкой: результат отправленного запроса может быть неопределённым.
Это исправление устраняет путь через WebSocket-таймер Desktop, но не гарантирует
отсутствие любых ошибок самого Desktop, ОС или реально упавшего сервера.

Установка: `deploy/upgrade_transport.ps1`. Новая схема включается при следующем
обычном запуске существующей иконкой «Codex + Telegram» после закрытия Desktop.
Установщик не закрывает открытые задачи и не изменяет Telegram-права или реквизиты.

Локальный отправщик уже установлен в ~/.codex/telegram-local.
Он запускается самим Codex как stdio MCP-процесс и соединяется с Telegram от личного аккаунта.
Контейнер и Linux не нужны. MCP автоматически запускает общий локальный брокер соединения.
Необязательный режим подписок ниже использует общий App Server на loopback-порту.

## Основные операции и MTProto streaming — 2.6.0

Read охватывает поиск сообщений, папки с составом чатов, историю с пагинацией и ветками,
сведения о чате и участниках, темы форума, конкретное сообщение и скачивание вложений.
Write охватывает отправку, редактирование, удаление, реакции, закрепление/открепление,
отметку прочтения и голосование. Дополнительные категории прав или миграция whitelist не нужны.
Каждое исходящее изменение требует поручения человека и UUID с долговечной квитанцией.

Доступен 21 инструмент с отдельными именами (telegram_search, telegram_folders,
telegram_chat_info, telegram_members, telegram_message, telegram_download, telegram_topics,
telegram_edit, telegram_delete, telegram_react, telegram_pin, telegram_mark_read, telegram_vote
и прежние восемь). Произвольных RPC или универсального action-интерфейса MCP нет.

Один автоматически запускаемый брокер держит соединение Telethon с receive_updates=True,
catch_up=True и обработчиком NewMessage. Новые сообщения поступают из MTProto Updates;
постоянного опроса истории больше нет. История запрашивается при baseline и ограниченном
восстановлении после подключения/разрыва. События редактирования и удаления пока не выдаются.
Поток сохраняется в ограниченную очередь SQLite, а подписки сохраняют прежние курсоры,
права, владельцев, сроки и защиту от повторной доставки. При переполнении — явный отказ,
без тихой потери сообщений. Отзыв read прекращает выдачу и очищает буфер.

Брокер принимает ограниченный JSON-протокол только на 127.0.0.1; случайный токен и порт
хранятся в private, не передаются агенту и не являются аргументами MCP. Он общий для чатов
Codex и редактора доступа, поэтому подписка не блокирует отправку или настройки.
Без активных подписок и операций он завершается после пяти минут простоя. Консоль не нужна.
Редактор остаётся только для человека; агент не получает доступ к его странице или выбору.

Скачанные файлы сохраняются с безопасными случайными именами в Downloads/Telegram Guard,
выдаются с SHA-256 и не исполняются. Изменение имени из Telegram не влияет на путь.
Глобальный поиск ограничен первой страницей; поиск в конкретном чате имеет пагинацию.
Ограничения Telegram по авторству, правам администратора и защищённому содержимому сохраняются.

Установка: deploy/upgrade_streaming.ps1. Обновляет код, скилл и только список инструментов/
таймаут Telegram в config.toml; не меняет whitelist, API-реквизиты или Telegram session.

Если работающий общий App Server запущен со старым allowlist, горячее перечитывание его
не заменяет. После завершения задач закрой Desktop и нажми существующую иконку
«Codex + Telegram». Launcher проверяет отсутствие активных чатов и принадлежность процесса,
пересоздаёт только свой устаревший сервер с явным списком 21 команды и открывает Desktop.
При активной задаче, открытом Desktop или неясной принадлежности перезапуск запрещается.

## Раздельные права чтения и отправки — 2.5.0

Чтение по умолчанию разрешено во всех доступных чатах, включая новые. На странице доступа
можно снять галочку «Чтение» у отдельных чатов — это blacklist. Кнопка «Разрешить чтение всех»
включает этот режим и очищает все исключения, независимо от текущего поиска.
Отправка настраивается отдельными галочками и по умолчанию запрещена. Разрешение чтения
или подписка никогда не включают отправку; поручение на каждое сообщение по-прежнему нужно.

Миграция `deploy/upgrade_permissions.ps1` сохраняет все прежние записи, их право отправки,
право чтения и лимиты. Прочие чаты становятся доступными только для чтения. Исходная политика
сохраняется в `whitelist.before-v2.*.json` только внутри защищённой папки Guard.
Миграция повторяема и не сбрасывает уже настроенную v2-политику.

История, watch и subscribe проверяют read. Отправка проверяет write. Для пересылки, существующего
медиа и историй проверяются read источника и write назначения. Отзыв чтения прекращает подписку
и удаляет очередь; отозванные сообщения не выдаются после ожидающего чтения.

`telegram_chats(search="...", limit=100, offset=0)` возвращает ID, названия, can_read/can_write
и next_offset. Чаты доступны для чтения без предварительного добавления в whitelist; нужный
peer разрешается внутри MCP, без выдачи access_hash. Секретные чаты не поддерживаются.
Broadcast-каналы доступны для чтения, галочка их отправки в редакторе недоступна.

Новая схема: version=2, прежние chats с данными peer и лимиты; read={default,allow,deny},
write={allow}. Deny сильнее default; один ID не может одновременно входить в allow и deny.
Legacy v1 до явной миграции сохраняет старое ограничительное поведение. Неверная политика
не превращается в разрешение по умолчанию. Редактор остаётся интерфейсом только для человека.

## Редактирование вайтлиста в браузере — 2.4.0

Скажи агенту «хочу отредактировать вайтлист тг» или «добавь чат N в тг».
Агент одной командой открывает локальную страницу в браузере по умолчанию:

```powershell
& "$env:USERPROFILE\.codex\telegram-local\telegram-whitelist.ps1"
# Необязательный поиск, без автоматического выбора:
& "$env:USERPROFILE\.codex\telegram-local\telegram-whitelist.ps1" -Search 'Название чата'
```

На странице есть список диалогов, поиск по названию/username/ID, фильтр выбранных чатов,
чекбоксы и сводка изменений. Текущий whitelist отмечен заранее. Поставь или сними галочки
и нажми «Сохранить изменения». Закрытие без сохранения ничего не меняет. Для каналов доступно
чтение; отправка через редактор не включается. Исчезнувшие из диалогов чаты можно убрать.

Агент только запускает редактор и передаёт ссылку. Он не читает страницу, не нажимает
чекбоксы и не сохраняет выбор. В MCP нет метода изменения whitelist. Поиск не выбирает
чат и не разрешает отправку сообщений. Инструкции: skills/telegram-send/references/whitelist-editor.md.

21.10.2026 пользователь явно разрешил этот запуск как исключение из правила «Telegram
только через MCP» и поручил закрепить его в глобальном AGENTS.md и скилле. Исключение
разрешает установленному редактору получать метаданные диалогов через Telethon для показа
человеку; агенту разрешён только запуск фиксированной команды, при необходимости вне песочницы.
Оно не разрешает агенту самому читать Telegram через Telethon, управлять страницей или менять whitelist.

Редактор слушает случайный порт только на 127.0.0.1 и закрывается через 30 минут либо по
кнопке «Закрыть». Одноразовый секрет передаётся непосредственно браузеру в URL-фрагменте,
удаляется из адресной строки и заменяется HttpOnly/SameSite cookie. Агент получает публичную
ссылку без секрета; она не открывает доступ в другом браузере. Проверяются Host, Origin,
сессия и CSRF. Чужие страницы не могут читать список или сохранять изменения.
API-реквизиты, session и access_hash не выдаются ни браузеру, ни агенту; сообщения не загружаются.

Сохранение атомарно, с проверкой версии и общим lock для браузера и старого CLI. Изменение
в другом окне требует обновить список. Лимиты отправки и прочие настройки сохраняются.
Это изоляция от штатного агента и посторонних сайтов, а не от произвольного процесса с
полными правами той же Windows-учётной записи; запрет автоматизации страницы также закреплён
в скилле. Редактор работает отдельно от MCP: перезапуск Desktop для него не нужен.

Установить обновление: deploy/upgrade_editor.ps1. Установщик обновляет код, ресурсы и скилл,
не читая и не меняя whitelist, private и глобальный config.toml. Вход в Telegram остаётся
личным действием пользователя через telegram-setup.ps1.

## Постоянное подключение в Codex Desktop

Стандартный режим на этом компьютере — обычный Desktop со всеми остальными инструментами.
Локальный telegram_guard включён в глобальном ~/.codex/config.toml; MCP запускается приложением.
Отдельный CLI, контейнер или служба не нужны.
После изменения конфигурации перезапусти telegram_guard в Настройки → MCP servers или перезапусти Desktop.
Для файловых ограничений выбери Custom (config.toml) под полем ввода: профиль telegram-desktop.
Существующий чат может сохранять прежний режим; глобальный default_permissions не доказывает,
что режим уже изменился в открытом чате.

Профиль наследует workspace, разрешает обычную работу с проектом и сетью,
оставляет sender/whitelist/skill/config только для чтения и запрещает чтение и запись private.
Браузер, Node REPL, Plane, плагины, apps, hooks и существующая политика approvals сохранены.
Это запрет в командной песочнице плюс инструкции агенту, а не абсолютная изоляция всех возможностей Desktop.
Full Access, одобренные команды вне песочницы и инструменты со своим файловым доступом имеют отдельные границы.
Пользователь явно принял это ограничение ради удобства.

Для другого компьютера после install_local.py запусти:
python deploy/configure_desktop.py --apply
Скрипт создаёт backup config.toml и проверяет, что остальные MCP, плагины, features,
approvals и пользовательские настройки семантически не меняются.
Скопируй skills/telegram-send в CODEX_HOME/skills. Добавь Telegram-инструкции в глобальный
AGENTS.md, чтобы запрет присутствовал в контексте каждого чата.
Login и управление whitelist остаются прежними; подключение само ничего не отправляет.

## Необязательный ограниченный CLI-профиль

Профиль ~/.codex/telegram-local.config.toml:
- разрешает обычную запись в рабочую папку;
- оставляет sender/runtime и whitelist.json только для чтения;
- закрывает private целиком: account.json, Telegram session и SQLite-аудит;
- закрывает изменение конфигурации Codex;
- устанавливает approval_policy=never: командный отказ не превращается в автоматическое выполнение вне песочницы;
- выключает другие MCP, plugins, apps, hooks, браузер и Computer Use только в этом профиле.

MCP запускается доверенным клиентом вне командной песочницы, поэтому он может читать сессию.
Агент получает telegram_chats, telegram_history, telegram_send, telegram_send_status и telegram_watch.
telegram_send принимает путь к локальному вложению с отдельной проверкой защищённых файлов.
Произвольные MTProto-запросы, экспорт сессии и управление whitelist отсутствуют в аргументах инструментов.

Правила read/deny технически применяются к командной песочнице. Отдельные возможности MCP и браузера имеют свои границы.
Поэтому одной строки deny без ограничения остальных инструментов недостаточно.
[Профили Codex](https://learn.chatgpt.com/docs/permissions).

**Граница гарантии:** проверен новый Codex runtime, запущенный с профилем telegram-local.
Full Access, другой профиль, произвольный MCP или другой процесс под обычной Windows-учётной записью не защищаются этим профилем.
Пользователь вне песочницы сохраняет возможность менять whitelist и входить в Telegram.
Это защита от агента внутри выбранного харнеса, а не системный запрет на использование аккаунта всеми программами компьютера.
Профиль не делает ограничения глобальными для других уже работающих чатов.

На установленном Codex 0.162.0-alpha.17.2 проверен native Windows elevated sandbox.
Этот backend требует root read; более узкий root deny был им отвергнут.
Поэтому используются точные исключения для Telegram private и запреты записи.
Изменение protected code, policy и profile, чтение session и доступ через hardlink фактически отвергнуты.

## Подключить аккаунт — один раз, лично

Нужно получить api_id и api_hash в [my.telegram.org](https://my.telegram.org).
Дальше в обычном PowerShell, не в командах агента:

```powershell
& "$env:USERPROFILE\.codex\telegram-local\telegram-setup.ps1" -Action init
& "$env:USERPROFILE\.codex\telegram-local\telegram-setup.ps1" -Action login
& "$env:USERPROFILE\.codex\telegram-local\telegram-setup.ps1" -Action dialogs
```

init запрашивает API-реквизиты. login запрашивает номер, код Telegram и 2FA.
Ввод кода и пароля скрыт; сессия не выводится и не экспортируется.

Выбери numeric ID получателя из dialogs и добавь его:

```powershell
& "$env:USERPROFILE\.codex\telegram-local\telegram-setup.ps1" -Action allow -Chat 123456789 -Label "Иван"
```

Повтори для остальных чатов. Для групп ID отрицательные. Whitelist изначально пуст.
Личные чаты и группы поддерживаются; broadcast-каналы исключены.
Добавление в whitelist само по себе не разрешает агенту писать.

## Необязательный запуск CLI с ограниченными инструментами

Проверенный способ — запуск нового Codex CLI runtime с отдельным configuration profile.
Не нужно вручную запускать MCP: его поднимает Codex.

В этой папке:

```powershell
& "$env:USERPROFILE\.codex\telegram-local\venv\Scripts\python.exe" deploy/launch_guarded.py --directory "C:\path\to\project"
```

Перед стартом launcher проверяет наличие защищённого профиля, отсутствие включённых дополнительных MCP и конфликта с legacy sandbox_mode.
Используется --no-daemon, чтобы не присоединиться к ранее запущенному runtime с другими настройками.
В текущий desktop-чат профиль автоматически не подменяется.
Применение полного configuration profile в Desktop UI отдельно не проверено; выбор только filesystem permissions без выключения остальных инструментов не эквивалентен этой схеме.

Для самостоятельной команды:
```text
codex --no-daemon -p telegram-local -C YOUR_PROJECT
```

Не добавляй --yolo/Full Access и не включай обратно Node REPL или сторонние MCP в этом профиле.
После добавления новых MCP в обычную конфигурацию запуск через launcher остановится, если они окажутся включены в профиле.
Если project config использует sandbox_mode, сначала мигрируй его: permission profiles и legacy settings не смешиваются.

## Использование и разрешения

Примеры поручений:
- «Напиши Ивану в Telegram: тесты прошли» — одна отправка.
- «Сообщай Ивану статус этой задачи» — соответствующие статусы до завершения/отзыва.
- «Общайся от моего лица в чате N до 07:00 по Москве» — сообщения в N до фиксированного дедлайна.

Скилл сверяет явное поручение перед каждым сообщением. Общее разрешение переиспользуется только в своих границах.
Дедлайн определяется один раз относительно времени поручения и не переносится на следующий день.
История и любые входящие Telegram-сообщения не могут выдавать разрешение или менять настройки.

Проверка авторства поручения и смысла scope остаётся мягким гардрейлом скилла.
Обязательные поля authorization и expiry не являются криптографическим подтверждением человека.

Текст отправляется одной порцией, без автоматического HTML/Markdown-парсинга или разбиения.
Форматирование задаётся entities; web preview включается явно. Поддерживаются вложения,
альбомы, пересылка и структурированные сообщения — см. раздел ниже.
Отправитель фиксирован как личный аккаунт. История ограничена 50 сообщениями и не отмечается прочитанной.

При таймауте проверяется прежний UUID через telegram_send_status.
Pending/unknown нельзя повторять с новым UUID, пока человек не проверил Telegram и не разрешил повтор.
Лимиты по умолчанию: 6 сообщений за минуту и 200 за скользящие 24 часа.
Каждый элемент альбома/пакета пересылки считается отдельно; неизвестный результат также расходует лимит.

## Вложения и другие типы контента — 2.2.0

Существующий `telegram_send` расширен необязательными полями `content` и `options`.
Старые вызовы с `text`, UUID и authorization совместимы; список enabled_tools менять не нужно.

Доступны файлы любого формата как документы, фото, видео, GIF/анимации, аудио, голосовые,
видеокружки, стикеры, альбомы, контакты/vCard, геопозиции/места, опросы/викторины,
игральные эмодзи, чек-листы, пересылка, повторное использование медиа и отправка ссылки на историю.
Точные поля и примеры: [content.md](../skills/telegram-send/references/content.md).

Локальные файлы копируются во временный снимок до загрузки. SHA-256 содержимого,
подписи, типы, настройки и authorization входят в привязку UUID. В аудит не пишутся байты файлов.
Ссылки/junction/hardlink, UNC, alternate streams и защищённые пути отсекаются до чтения.
Whitelist и срок разрешения проверяются повторно во время загрузки и перед отправкой.

Если операция занимает более 20 секунд, MCP возвращает `pending`, продолжая загрузку.
Результат проверяется тем же UUID через `telegram_send_status`. SQLite хранит все ID сообщений
альбома; при неполном подтверждении результат остаётся неизвестным. Перезапуск MCP обрывает
активные операции: не перезапускай его до проверки отправок со статусом `pending`.

Тип файла не ограничен, но действуют ограничения Telegram на размер, кодек, подписку и права
в чате. Локальный предел — 4 GiB на файл; аккаунт может иметь меньший предел.
Live location передаёт начальную точку и период, без автоматического отслеживания координат.
Создание бот-игр/инвойсов/клавиатур, оплаты, платные посты, секретные чаты и публикация
историй не входят в этот отправщик личного аккаунта. Broadcast-каналы по-прежнему исключены.

Реализация использует [Telethon 1.45](https://docs.telethon.dev/en/stable/modules/client.html)
и [типизированные Telegram InputMedia](https://core.telegram.org/type/InputMedia).

## Фоновые входящие сообщения — 2.1.0

Добавлен telegram_watch: первое чтение фиксирует курсор, последующие возвращают только
новые входящие сообщения; свои отправки продвигают курсор без эха.
Ожидание ограничено 45 секундами и выполняется в фоновой задаче харнеса, которая передаёт
новые данные через notify(), пока основной агент продолжает работу.
В текущем харнесе доставка фонового события проверена без вызова wait в основном агенте.
Автоматическое пробуждение после завершения/закрытия чата не подтверждено.

Пример поручения: «Следи за сообщениями Ивана следующие 10 минут, пока я работаю».
Это разрешает наблюдение; разрешение отвечать выдаётся отдельно.
Данные приходят как внешний результат инструмента, а не как системные инструкции.
Подробности и скрипт фоновой задачи — в skills/telegram-send/references/incoming.md.
После обновления нужно Restart для telegram_guard в Desktop.

## Подписки с пробуждением сессии — 2.3.0

Добавлены telegram_subscribe, telegram_subscriptions и telegram_unsubscribe. Подписка
привязана к threadId из метаданных MCP-вызова. Адрес сервера и чужой thread ID не принимаются
как аргументы. Нужны поручение человека наблюдать за чатом и фиксированный expires_at;
срок — до 7 дней, одновременно до 8 подписок. Начальная точка пропускает историю.

Guard опрашивает Telegram внутри MCP и отправляет результаты через turn/start.toolOutput.
Данные поступают как function_call_output: idle-сессия просыпается, активная получает событие
в текущем ходе. Это не разрешает отвечать в Telegram. Сообщения содержат текст до 4096 символов,
тип медиа и ID; файлы автоматически не скачиваются. Срок и whitelist проверяются повторно.

Курсор и очередь сохраняются в private/subscriptions.sqlite3. Lease исключает параллельную
доставку двумя MCP-процессами. Если подтверждение после отправки потерялось, состояние становится
delivery_unknown без автоматического повтора. Exactly-once не обещается: App Server не даёт
идемпотентный ключ события. Unsubscribe удаляет очередь, но уже отправленное событие не отзывает.

Обычный Desktop использует stdio. В установленной версии найден внутренний параметр
CODEX_APP_SERVER_WS_URL для подключения Desktop к общему runtime. Он не документирован как
стабильная пользовательская настройка и может измениться после обновления приложения.

### Включение на этой машине

На панели задач закреплён **Codex + Telegram**: он открывает Desktop и native stdio bridge
через pythonw, без консоли. Такой же ярлык есть на рабочем столе и в меню Пуск.
Для первого переключения заверши задачи, закрой обычный Codex и нажми новую иконку.
Если Codex уже открыт, launcher покажет понятное сообщение и не прервёт его задачи.
После обновления Desktop проверка версии по-прежнему требует обновить launcher.
Установка ярлыков на другом компьютере: `deploy/install_shortcut.ps1`.

Установщик: deploy/upgrade_subscriptions.ps1. Глобальный config.toml, whitelist и Telegram
private он не изменяет. Новые enabled_tools и endpoint передаются как параметры только
при запуске общего App Server. Версия исполняемого файла проверяется перед запуском.

1. Завершить активные задачи и штатно закрыть Desktop.
2. В обычном PowerShell выполнить:

```powershell
& "$env:USERPROFILE\.codex\telegram-local\shared-desktop.ps1" -Action Start
```

Launcher открывает Desktop; ограниченный event endpoint появляется после старта native stdio bridge.
Он не завершает работающий Desktop, не заменяет модель/permissions/approval policy и не
меняет постоянные переменные окружения. Порт доступен локальным процессам и предоставляет
доступ к App Server; не публикуйте его в сеть и не используйте перенаправление порта.

3. Открыть прежнюю задачу. После проверки доступности восьми telegram_guard tools можно
поручить наблюдение: «Следи за чатом N следующие 30 минут». Поручение на отправку выдаётся отдельно.

21.10.2026 после запуска пользователем подтверждены подключение реального Desktop, наличие
прежнего thread и доставка синтетического события в активный ход. Доступны все восемь
telegram_guard tools. Пробуждение idle проверено отдельно на изолированном App Server с
локальной заглушкой модели. Подробные результаты и границы проверки — в docs/verification.md.

Возврат к обычному режиму: закрыть Desktop, выполнить команду ниже, затем открыть приложение
из меню Пуск. Launcher завершает только собственный App Server, сверяя PID, путь и время запуска.

```powershell
& "$env:USERPROFILE\.codex\telegram-local\shared-desktop.ps1" -Action Stop
```

Проверка без запуска: та же команда с -Action Check. Если приложение обновилось, сначала
повторить integration probe и обновить пути/версию в shared-desktop.json.
